# dora-mcp

An [MCP](https://modelcontextprotocol.io) server that gives AI assistants such as Claude Code read-only access to records of software delivery, and the [DORA metrics](https://dora.dev/guides/dora-metrics/) calculated from them.

For now it runs against a database of made-up records, generated by `dora-seed`.

## Tools

| Tool | What it does |
|---|---|
| `list_services` | Lists the services, their teams and the dates the data covers. |
| `get_dora_metrics` | Calculates the metrics for a period, for one service, one team or all of them. |
| `compare_dora_metrics` | Calculates the metrics for each service or each team side by side. |
| `get_dora_trend` | Calculates the metrics for each week, month or quarter of a period. |
| `list_deployments` | Lists the deployments made in a period, with what each shipped and broke. Filters by failure and remediation. |
| `list_incidents` | Lists the incidents that started in a period, or those caused by deployments made in it. Filters by severity, status and cause. |
| `summarise_incidents` | Counts incidents by service, team or severity, including those no deployment caused. |
| `get_deployment` | Shows one deployment: its commits and the incidents it caused. |
| `find_commit` | Traces a commit, by SHA or a prefix of one, to the deployment that shipped it. |

A team's metrics pool the deployments of all its services, rather than averaging the services' rates.

The tools take values (dates, names, a fixed set of choices), never SQL. Every query the server runs is written in `internal/store`, with the values bound as parameters, so a caller can only choose among those queries. The database is also opened read-only.

The metrics are:

- deployment frequency
- lead time for changes (from commit to production)
- change failure rate
- failed deployment recovery time
- rework rate

A metric with no data to calculate it from is `null`, not zero.

## Setup

You need [Devbox](https://www.jetify.com/devbox), which provides Go and golangci-lint at the versions pinned in `devbox.json`.

```sh
devbox run -- task build   # compile bin/dora-mcp and bin/dora-seed
devbox run -- task seed    # create data/dora.sqlite with made-up records
```

Then start Claude Code in this directory. It reads `.mcp.json`, asks you to approve the `dora` server, and launches `bin/dora-mcp` for the session.

To use the server from another project, register it there with an absolute path:

```sh
claude mcp add dora -- /path/to/dora-mcp/bin/dora-mcp -db /path/to/dora-mcp/data/dora.sqlite
```

## Running over HTTP

By default the server talks MCP over stdin and stdout, as a process its client starts. It can serve MCP's Streamable HTTP transport instead:

```sh
bin/dora-mcp -transport http -addr 127.0.0.1:8080
```

The HTTP mode has no authentication, so keep it on `127.0.0.1`. It must have authentication added before it listens anywhere other people can reach.

## Development

```sh
devbox run -- task test    # go test ./...
devbox run -- task lint    # golangci-lint run
devbox run -- task fmt     # format and sort imports
```

Layout:

```
cmd/dora-mcp/      the server program
cmd/dora-seed/     the program that makes the fake database
internal/dora/     the metric calculations, free of storage and MCP
internal/store/    SQLite access and the schema
internal/seed/     the fake-data generator
internal/server/   the MCP tools, free of any transport
```

The database and compiled programs are gitignored. Recreate them with `devbox run -- task seed` and `devbox run -- task build`.
